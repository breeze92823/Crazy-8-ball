# Crazy 8 Ball

A rooftop pool lounge hub (original design, inspired by the genre): walk onto a glowing join pad beside a table (1v1 / 2v2 / 3v3), the table fills with players, and an 8-ball match starts on that table. The hub sits on a skyscraper above a city at golden hour (N = night).

## Repos
- Frontend (this repo): `C:\ThreeJS\Crazy-8-ball\Crazy-8-ball`. It was copied from Bowling Roll; old code is in git `HEAD` (`git show HEAD:src/<file>`).
- Backend: `C:\ThreeJS\Crazy-8-ball\Crazy-8-ball-backend` (Colyseus + MongoDB; its CLAUDE.md lists every message). `src/net.js` joins room `world` (dev: `ws://localhost:2567`, launch config `crazy-backend`; prod: the Bloxity SDK resolves the pod). Other hub players are simulated bots plus the real players in the room (`remotePlayers.js`).
- Dev server: `.claude/launch.json` in the parent folder, config `crazy-dev` (port 5231, `VITE_DEV_MODE=true`).

## The hub (`src/hub/`)
- `rooftop.js` tower + tiled roof, parapet/glass railing (invisible walls 3.2 m), instanced city with a world-space window shader (lit windows follow `lighting.windows()`), streets, islands.
- `layout.js` everything else on the roof (lounge pavilion with sofas, fire pit, piano and string lights; leaderboard stands; entrance arch with the title sign; elevator; showcase pedestals; cabana; umbrellas; cherry trees, pines, planters, ferns; lantern bollards; night lamps). Static props are baked (`bake.js`). `floorAt(x, z)` = floor height (the lounge deck is raised 0.4 m).
- `props.js` the procedural models (pool table, cue, sofa, piano, trees, ferns, umbrella, lounger, pergola, ...). `paint.js` canvas painters (floor, wood, felt, balls, pad decals, chevrons, flags, boards, sign).
- `tables.js` tables, join pads (decal + rising hologram rings + JOIN arrows), instanced balls, lobby states `open -> waiting -> countdown -> playing (bots) | match (player) -> cooldown`. Bot games are real simulations. `tablesim.js` 2D billiards physics + `pickShot` AI.
- `bots.js` simulated players (wander, join pads, play, aim pose; `fillFor(table)` sends bots to the player's table). `nav.js` grid A* used by bots and the guide.
- `match.js` + `match.css` the player's match: "WHO BREAKS?" roulette, then a 3D camera behind the cue ball (wheel / pinch / W-S zoom from low behind the cue to a high view; views `aim` / `watch` overview while balls roll / `hub` = the chase cam during the opponent's turn, blended). Drag to aim (fine-aim toggle, A/D), PULL bar or Space for power, spin + cue elevation panel (follow/draw, side english off cushions, masse in `tablesim.js`), ghost-ball guide (tube, object/cue lines, target-pocket ring, green/red ball outlines, INVALID FIRST TARGET), ball in hand ("MOVE", drag the cue ball), banners (FOUL!, OPPONENT'S TURN, YOU ARE SOLIDS), STREAK xN, shot-clock pill, player cards with ball racks, exit + confirm, result card. First match = guided tutorial (break, drag, zoom out, zoom in, shoot; `save.tutorialDone`). ABILITY bar fills on own pots (`save.ability`); at 100% G / tap the ability button uses the EQUIPPED ability (see Abilities below; `armed` = the id armed for my next shot, `shotAb` = the one riding on the shot in flight). `M.debug.give(id)` (dev) equips any ability with a full bar. Rewards cash only (`ECONOMY.potReward` per own pot x streak, win/loss), never premium currency. `M.debug` (dev only) exposes state hooks.
- `matchfx.js` match effects: pooled point particles (chalk puff, impact sparks, rail dust, pocket burst + light rays, fire trail, embers, `sparkle`, `suck`), scorch decals, the cue-ball aura (fire, or tinted per ability via `TINT`).
- `guide.js` chevron trail to the target pad; `fx.js` petals, pad sparkles, confetti + ring, fire, fireflies; `boards.js` leaderboards (sample data); `hud.js` + `hud.css` DOM HUD (tutorial line, settings, players list, skip tutorial, cash, streak, leave button, lobby bar `n/cap Starting in 3`, name tags, table card, popups).
- `src/audio/` synthesised audio: `core.js`/`synth.js` (from the old game), `sfx.js` (UI, pads, footsteps, cue/ball/rail/pocket sounds, match juice: power ratchet, roulette, tutorial chimes, streak, ability, fire shot, foul, clock ticks, looped rolling rumble `setRoll`), `ambience.js` (wind, city, birds/crickets, fire, chimes, generative lounge piano), `index.js` (`at(x, z)` positional gain/pan).
- Tunables: `ROOF`, `CITY`, `FACADE`, `TABLE`, `TABLE_MODES`, `TABLE_GRID`, `PAD`, `LOBBY`, `BOTS`, `ECONOMY`, `MATCH`, `AUDIO` in `config.js`.

## Players panel, emotes, remote players
- Players panel (`hud.js` `setPlayers`, top right "Players (n)" pill -> panel): everyone in the hub (you first, then by wins) with hexagon rank badge (tier colour by rank 0..8), name, flag, Wins and Money (`money()`: $21,941 / $295K / $1.2M). Entities need `name, flag, rank, wins, cash`; bots get a matching history (`bots.js`) and earn `ECONOMY.winReward/lossReward` per bot game.
- `emotes.js`: the emote catalog (18, all free; ids match the backend `ID_PATTERN`). `pose(o, t)` writes a PoseBuffer in character space (negative elbow X folds the forearm up/forward; an arm raised sideways folds about Z), may set `o.bobY`, returns extra root yaw. `loop` emotes run until the player moves, others stop after `dur`. `avatar/animator.js` `playEmote(def)` / `stopEmote()` / `emoteId` blends it over the locomotion pose while standing.
- `hub/emotemenu.js` + `.css`: EMOTE button (bottom right; above the touch thumb arc on touch) and the Emotes panel (3-col grid of silhouettes rendered once from the rig at each emote's `thumb` time, star = favourite -> sorted first, `crazy-8-ball.emoteFavs` in localStorage; footer = selected emote + Avatar Shop = `bloxity.toggleCustomizer` when available). B toggles; hidden in a match. Bots emote now and then while idle (`BOTS.emoteChance`) and celebrate wins.
- `remotePlayers.js`: real players in the same server room (net.js `net.room.state.players`), drawn with their Bloxity look + equipped cue, dead-reckoned (`REMOTES` in config), playing their emotes (`emote` / `emoteSeq`), listed as hub entities (name tags + Players panel). It also sends this player's `pose` (10 Hz), `stats` { wins, cash, rank, flag }, `setAvatar` look and `emote` { id } ('' = stopped) through net.js `sendServer`.

## Progress, cues and rewards
- `progress.js` owns `save` (cash, wins, streak, tutorialDone, ability 0..100, xp, rankClaimed, tag, cues {id: count}, cue, bag [{uid, kind, readyAt}], hotbar [uid], perks, playtime) + device `settings` (localStorage only). Change it only through its actions (addCash/spend, grantCue/equipCue/sellDupes/buyRarity/buyCue, grantBlock/openBlock/toHotbar, grantReward, addXp -> pays rank levels, tutorialFinished, claimBonus); they fire `onChange(key)`. `snapshot()` / `hydrate()` / `settle()` (one-off grants: the Time Gift block, Starter Cue).
- `net.js`: `progress` / `noProgress` / `serverError` load, debounced `saveProgress`, a browser copy (`ECONOMY.storageKey`) used offline. Server-authoritative Daily (`claimDaily`, `unlockAllDaily` — cash is spent client-side first and refunded on failure), Track (`claimTrack`) and Playtime gifts (`claimGift`, `giftSecs()`); without a server the same rules run locally (`crazy-8-ball.rewards`). Generic `request(type, payload, answer)`, `onServer(type, fn)`, `sendServer` for other features.
- `cues.js`: the 78-cue catalog (`CUES`, `RARITIES` with Index price / sell value, `HOW`, `CUE_PRICES`), lucky `BLOCKS` and odds (`rollBlock`, `chanceOf` = Mystery block chance), canvas thumbnails (`cueThumb`, `blockThumb`) and the 3D look (`applyCueLook(buildCueGroup, id)`: the player's hand cue, the table cue on my shots, bot cues).
- `hub/menus.js` + `menus.css`: left buttons (Cues, Rewards, Ranked), windows Cues (My Cues: search, sort, sell dupes; Index: rarity sections, buy a random cue of a rarity, detail panel), Free Reward (Daily 7 days + unlock all, Playtime gifts, 28-day Track, Bonus), Ranked (tier carousel, current rank + XP, division rewards), Bag + hotbar (keys 1-6 open ready blocks), reveal card (block roll, rank up). Tunables `DAILY`, `TRACK`, `GIFTS`, `BONUS`, `STARTER`, `BAG`, `RANKED`, `NET`, `SERVER_URL` in config.js. Everything is bought with cash, never premium currency.

## Abilities (Ability Spin)
- `src/abilities.js`: the catalog (15 abilities in 6 rarities `ABILITY_RARITIES` Common 55 / Uncommon 30 / Rare 12 / Epic 2 / Legendary 0.67 / Mythic 0.1 %, even split inside a rarity), SVG icons (`abilityIcon`), the rules `ABILITY_SPIN` (start = Fire Shot in slot 1 + 1 free spin; 3 slots, slot 2/3 cost $25K/$100K; pity: the 100th spin without an Epic+ is one; cash spin packs 1/5/10/50 = $10K/$47.5K/$90K/$425K, the yellow bar buys 1 and spins it; codes FREESPINS = 5, 120KLIKES = 3, once each) and the local engine (`abilityOps`, `rollAbility`). Mirrored by the backend `src/abilities.ts`: a contract change goes in both. Never premium currency.
- `hub/abilityStore.js`: the player's ability state. Signed-in players: server-authoritative (`abilities` view after load, actions -> `abilityResult` { ok, action, reason?, ..., state }); guests / no server: the same rules on a browser copy (`crazy-8-ball.abilities`). Cash is spent client-side first and refunded on a refusal (like Daily unlock-all). `mode()` 'server' | 'offline' | 'local'; `equippedId()` = the ability a match uses.
- `hub/abilityScreen.js` + `.css`: the screen from the reference (slots with EQUIP / lock / NEW SLOT, CURRENT ABILITY title + reel, code box, SPIN + spins left, Odds accordion + pity bar, packs + quick bar, Back, rarity reveal card). Its button joins the menus' left stack (`.mn-side`); while open the camera faces the player (`frameCamera`, main.js), walking is locked and the hub HUD / touch UI hide. Portrait phones restack it (Odds becomes a sheet).
- `hub/abilityPlay.js` (+ `abilityPlay.css`): the in-match effects. Most abilities arm the next shot and pass tablesim `shoot(..., mods)` (railE / cueRailE, cueMass, ghost, timed `pulls` incl. swallowing, portals, noScratch, onCueHit); Look Over There! acts at once on the opponent's next shot; Rewind and Time Stop change the turn logic in match.js `resolve()`; Catch-a-Ball nudges a ball when the table settles; Eagle's Eye simulates the shot on a ghost sim. A 16 s safety stop ends any shot. `audio/abilitySfx.js`: spin screen + ability sounds.

## Base (kept from the template)
Three.js (vanilla, no React) + Vite + Rapier (`@dimforge/rapier3d-compat`, wasm inlined; `main.js` awaits its init at top level, hence `build.target: 'es2022'`). Everything is procedural (canvas textures); the only imported model is the Bloxity base rig `public/avatars/player.glb`. Font: Fredoka (loaded in `index.html`).

- `npm run dev` / `npm run build`. `VITE_DEV_MODE=true` (see `.env.example`) skips the Bloxity SDK/CDN. Deploy: `.github/workflows/deploy.yml` uploads `dist/` to Bloxity Hosting (main = prod, dev = dev channel).
- All Bloxity SDK calls go through `src/bloxity.js` and must never throw (SDK may be blocked).

## Files (`src/`)
- `main.js`: boot order = Bloxity SDK -> renderer -> Rapier -> sea + clouds, lighting, ground slab + colliders, player body -> avatar (async, swaps in when ready) -> loop (physics, interpolate player, avatar animator, camera, sea ripples, lighting, bloom render). `__game` (dev only) exposes `player`, `scene`, `renderer`, `camera`, `postfx`, `bodies`, `toggleMode`, `teleport(x, y, z, facing)` (facing `Math.PI` = north, -Z).
- **Player**: `player.js` kinematic capsule + Rapier `KinematicCharacterController` (autostep, slopes, snap-to-ground, pushes dynamic bodies), own gravity/jump (coyote time + buffer). Feet position is `player.position`; `player.renderPosition` is interpolated for drawing. Falling below `PHYSICS.killY` respawns. `camera.js` third-person chase cam (boom, wheel zoom, wall clearance via `segmentClear`, speed FOV) and first person at the inner zoom end; `modes.js` `character` (avatar visible) / `player` (first person, avatar hidden), V toggles. `input.js` keyboard / mouse / pointer lock into `inputState`; `touch.js` + `touch.css` touch controls.
- `avatar/`: `character.js` (player.glb or procedural fallback), `loader.js` (Bloxity cosmetics + proportions from the CDN, `cdn.js`), `rig.js` + `animator.js` (procedural idle/run/airborne/landing; tunables in `ANIM`).
- **Physics**: `physics.js` Rapier world, fixed 60 Hz step with an accumulator; dynamic meshes bound via `bindMesh`/`addDynamic` are interpolated between ticks. Static geometry uses `addFixed` / `addFixedBoxFor`. `segmentClear` is the camera's ray against static colliders only.
- **Sea + clouds**: `world.js` `createWorld(scene)` (the sea at street level + clouds). `buildGround`/`landColliders` (the old sand slab) are unused.
- **Sky and light**: `lighting.js` sky shader, stars, PMREM environment, shadowed sun following the player, fog, day/night blend (N). `addLamp` and `setMoods(sky)` are unused hooks. `postfx.js` bloom (EffectComposer: HDR half-float render -> UnrealBloomPass -> OutputPass), on for the High/Ultra presets only (`BLOOM`; threshold 2.0 so sunlit surfaces never bloom).
- **Materials and textures**: `textures.js` canvas painters (cracked sand, water ripples, grass/tiles/crates/planks, outlined text, soft dots, sparkles, ...) and `toTexture` / `mulberry32`. `propkit.js` shared prop helpers: `std`, `glow`, `neon(color, k)` (unlit, HDR-bright with bloom; switched by `setNeonBloom`), `put`, `solidBox` / `solidPole` colliders, `label` (outlined text sprite, repainted once Fredoka loads). `bake.js` merges a Group's static meshes to one mesh per material (draw-call saver; unused so far).
- Controls: WASD/arrows, Shift sprint, Space jump, mouse look (click grabs the cursor = pointer lock, Esc releases it, then Esc opens the portal menu), wheel zoom, V mode, N day/night, R respawn. Never bind P (CrazyGames: Boxity's pause menu).
- Graphics: `graphicsPreset(name)` in config resolves the preset; on coarse pointers the default is Medium and every preset is capped by `MOBILE_GRAPHICS_CAP` (DPR 1.5, 1024 shadow map, no bloom), because the Bloxity SDK sends `High` itself.
- Boxity layout (required to publish, docs.bloxity.io Platform UI rules): Boxity draws the menu / pause menu, chat, emotes, avatar editor, invite, leaderboard and sign-in itself in a toolbar in the top-left corner with the chat feed under it, so the game never draws those buttons (exception, the owner's decision: the in-game EMOTE button + Emotes panel, `hub/emotemenu.js`, stay) and keeps any HUD out of those rectangles (`bloxity.onReservedAreas`).

## Mobile & responsive (required for every change)
The game must play on phones and tablets (portrait and landscape) as well as desktop. Treat a feature as unfinished until it works on touch and on a small screen.
- **Input**: every action needs a touch path, not just a key. Use Pointer Events (`pointerdown/move/up`, check `e.pointerType`), never mouse-only events. Layout (implemented in `src/touch.js`): left-thumb virtual joystick -> `inputState.move`, right-side drag -> `inputState.look`, on-screen buttons for jump/sprint/mode/etc., pinch -> `inputState.zoom`. Everything still feeds `inputState` in `src/input.js` so game code stays input-agnostic. Pointer lock does not exist on touch; never rely on it.
- **Detection**: decide touch UI with `matchMedia('(pointer: coarse)')` / `navigator.maxTouchPoints`, not the user agent. Show touch controls only on coarse pointers; a device can have both.
- **Layout/UI**: HUD and menus use relative units (`%`, `vw/vh`, `dvh`, `clamp()`) and flexbox/grid, no fixed pixel layouts. Tap targets >= 44px. Respect notches with `env(safe-area-inset-*)` (viewport already has `viewport-fit=cover`). Text readable at 360px width. No hover-only interactions. Add `touch-action: none` on the canvas and game controls so the browser does not scroll/zoom.
- **Resize/orientation**: anything sized to the screen (camera aspect, renderer, HUD) must react to `resize` (covers orientation changes). Use `visualViewport` where the on-screen keyboard or browser bars matter.
- **Performance**: mobile GPUs are weak. Respect the `graphics_quality` presets in `src/config.js` (cap DPR, shadow map size, draw distance); default to a lower preset on coarse-pointer devices. Avoid per-frame allocations; keep draw calls and texture sizes low.
- **Testing**: check every UI/input change at a phone viewport (e.g. 375x812 and landscape 812x375) with touch emulation, plus desktop, before calling it done.
