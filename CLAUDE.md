# Crazy 8 Ball

A rooftop pool lounge hub (original design, inspired by the genre): walk onto a glowing join pad beside a table (1v1 / 2v2 / 3v3), the table fills with REAL players (no bots anywhere: matches only start when every seat is a player in the same server room), and an 8-ball match starts on that table. The hub sits on a skyscraper above a city at golden hour (N = night).

## Repos
- Frontend (this repo): `C:\ThreeJS\Crazy-8-ball\Crazy-8-ball`. It was copied from Bowling Roll; old code is in git `HEAD` (`git show HEAD:src/<file>`).
- Backend: `C:\ThreeJS\Crazy-8-ball\Crazy-8-ball-backend` (Colyseus + MongoDB; its CLAUDE.md lists every message). `src/net.js` joins room `world` (dev: `ws://localhost:2567`, launch config `crazy-backend`; prod: the Bloxity SDK resolves the pod). The other hub players are the real players in the room (`remotePlayers.js`); there are no bots. Dev: `?dev=name` picks the dev identity, so two tabs can play each other (a background tab pauses its render loop: front the shooter's tab).
- Dev server: `.claude/launch.json` in the parent folder, config `crazy-dev` (port 5231, `VITE_DEV_MODE=true`).

## The hub (`src/hub/`)
- `rooftop.js` tower + tiled roof, parapet/glass railing (invisible walls 3.2 m), instanced city with a world-space window shader (lit windows follow `lighting.windows()`), streets, islands.
- `layout.js` everything else on the roof (lounge pavilion with sofas, fire pit, piano and string lights; leaderboard stands; entrance arch with the title sign; elevator; showcase pedestals; cabana; umbrellas; cherry trees, pines, planters, ferns; lantern bollards; night lamps). Static props are baked (`bake.js`). `floorAt(x, z)` = floor height (the lounge deck is raised 0.4 m).
- `props.js` the procedural models (pool table, cue, sofa, piano, trees, ferns, umbrella, lounger, pergola, ...). `paint.js` canvas painters (floor, wood, felt, balls, pad decals, chevrons, flags, boards, sign).
- `tables.js` tables, join pads (decal + rising hologram rings + JOIN arrows), instanced balls, lobby states `open -> waiting -> countdown -> match -> cooldown`, set from the server (`setMembers(t, [[entity], [entity]])`, `setState(t, state, timer)`); offline `join`/`leave` only seat this player locally and no match starts. `tablesim.js` 2D billiards physics + `pickShot` (the initial aim suggestion, Verity).
- `tablenet.js` the server's tables (backend `tables.ts`): `join(zone)` / `leave()` send `padJoin` { table, team } / `padLeave` (the seat shows at once, held `PENDING_MS` until the roster confirms), mirrors `room.state.tables` every frame, starts my match on `matchStart`, and draws every table I'm not shooting on from the shooter's stream (`mAim` cue turning, `mShot` stroke, `mBalls` positions + sound events interpolated ~110 ms behind, `mTurn` settled balls). Wire helpers `packBalls` / `applyBalls` / `packEvent` (16 x [x, z, on] in 1e-4 m; events [code, n, speed x100, x, z]).
- `stance.js` `attachCue` (cue in the right hand) and `aimPose` (leaning over the cue; remote shooters lean while their `mAim` arrives, `entity.aimUntil`). `nav.js` grid A* used by the guide.
- `match.js` + `match.css` the player's match against real players. The shooter's client runs the physics + rules and streams them (`mAim` 10 Hz, `mShot`, `mBalls` ~15 Hz, then `mEnd` { balls, turn, groups, bih, foul, note: group|rewind|timeStop|rerack|kitchen, winner, why, distract }); everyone (the shooter too) moves on when the server's `mTurn` arrives (`applyTurn`: banners, ball in hand, next shooter; a team's players take turns). Phases: roulette, intro, aim, strike, rolling, wait (my mEnd sent), remote / remoteRoll (someone else's shot, tablenet draws it; overview camera while it rolls), pause (after a foul), over. Shot clock `MATCH.shotClock` (`tutorClock` in the tutorial): running out sends a foul. Leaving = `mForfeit` (forfeit); losing the server room ends the match. Look Over There! travels in mEnd (`distract`) and makes the next opponent's shot go wild on their client. Remote ability shots show a banner + tinted aura only. "WHO BREAKS?" roulette (the server picks), then a 3D camera behind the cue ball (wheel / pinch / W-S zoom from low behind the cue to a high view; views `aim` / `watch` overview while balls roll / `hub` = the chase cam during the opponent's turn, blended). Drag to aim (fine-aim toggle, A/D), PULL bar or Space for power, spin + cue elevation panel (follow/draw, side english off cushions, masse in `tablesim.js`), ghost-ball guide (tube, object/cue lines, target-pocket ring, green/red ball outlines, INVALID FIRST TARGET), ball in hand ("MOVE", drag the cue ball), banners (FOUL!, OPPONENT'S TURN, YOU ARE SOLIDS), STREAK xN, shot-clock pill, player cards with ball racks, exit + confirm, result card. First match = guided tutorial (break if you break, drag, zoom out, zoom in, shoot; ball in hand only when the turn really has it; `save.tutorialDone`). ABILITY bar fills on own pots (`save.ability`); at 100% G / tap the ability button uses the EQUIPPED ability (see Abilities below; `armed` = the id armed for my next shot, `shotAb` = the one riding on the shot in flight). `M.debug.give(id)` (dev) equips any ability with a full bar. Rewards cash only (`ECONOMY.potReward` per own pot x streak, win/loss), never premium currency. `M.debug` (dev only) exposes state hooks.
- Rules (`resolve()`, WPA-style 8-ball, judged by `shotPre` = the table before the shot): the breaker has ball in hand behind the head string (`kitchen`; not in the tutorial); a legal break pots a ball or sends 4 object balls to a cushion (tablesim `railBalls`), else re-rack and the other team breaks (`rerack`); potting on the break keeps the turn, an 8 on the break is spotted; a scratch on the break = ball in hand behind the head string (`kitchen`). Open table after the break: one group potted takes it, both = the first ball hit (if it dropped). Fouls (other team: ball in hand anywhere, no move timer): scratch, no ball hit, wrong ball first (on the 8: anything but the 8), no ball potted and no cushion after contact (tablesim `railAfter`), shot clock. On the 8 the shooter calls a pocket (`callPocket`: `.mt-call` markers, tap one; until then it follows the guide's pocket; sent as `mAim.k` so the others see it): the 8 in the called pocket wins; early, in another pocket, or with a foul loses.
- `matchfx.js` match effects: pooled point particles (chalk puff, impact sparks, rail dust, pocket burst + light rays, fire trail, embers, `sparkle`, `suck`), scorch decals, the cue-ball aura (fire, or tinted per ability via `TINT`).
- `guide.js` chevron trail to the target pad; `fx.js` petals, pad sparkles, confetti + ring, fire, fireflies; `boards.js` the hub's TOP PLAYERS / TOP COUNTRIES boards, live from the server's `leaderboard` message (main.js `onServer`; "Loading..." until it arrives, "No wins yet" when empty); `hud.js` + `hud.css` DOM HUD (tutorial line, settings, players list, skip tutorial, cash, streak, leave button, lobby bar `n/cap Starting in 3`, name tags, table card, popups).
- `src/audio/` synthesised audio: `core.js`/`synth.js` (from the old game), `sfx.js` (UI, pads, footsteps, cue/ball/rail/pocket sounds, match juice: power ratchet, roulette, tutorial chimes, streak, ability, fire shot, foul, clock ticks, looped rolling rumble `setRoll`), `ambience.js` (wind, city, birds/crickets, fire, chimes, generative lounge piano), `music.js` (calm generative background music in D major on its own band-limited `A.music` bus: pad + bass + sparse e-piano melody; ducks near the lounge piano and in a match; HUD "Background music" slider + Boxity `music_volume`), `index.js` (`at(x, z)` positional gain/pan).
- Tunables: `ROOF`, `CITY`, `FACADE`, `TABLE`, `TABLE_MODES`, `TABLE_GRID` (its order = the backend's `TABLE_TEAMS`), `PAD`, `BOTS` (only the default looks of players without an avatar), `ECONOMY`, `MATCH`, `AUDIO` in `config.js`.

- `hub/emotemenu.js` + `.css`: EMOTE button (bottom right; above the touch thumb arc on touch) and the Emotes panel (3-col grid of silhouettes rendered once from the rig at each emote's `thumb` time, star = favourite -> sorted first, `crazy-8-ball.emoteFavs` in localStorage; footer = selected emote + Avatar Shop = `bloxity.toggleCustomizer` when available). B toggles; hidden in a match.
- `remotePlayers.js`: real players in the same server room (net.js `net.room.state.players`), drawn with their Bloxity look + equipped cue, dead-reckoned (`REMOTES` in config), playing their emotes (`emote` / `emoteSeq`), listed as hub entities (name tags + Players panel; `bySid(sid)` for the tables). ## Mobile & responsive (required for every change)
The game must play on phones and tablets (portrait and landscape) as well as desktop. Treat a feature as unfinished until it works on touch and on a small screen.
- **Input**: every action needs a touch path, not just a key. Use Pointer Events (`pointerdown/move/up`, check `e.pointerType`), never mouse-only events. Layout (implemented in `src/touch.js`): left-thumb virtual joystick -> `inputState.move`, right-side drag -> `inputState.look`, on-screen buttons for jump/sprint/mode/etc., pinch -> `inputState.zoom`. Everything still feeds `inputState` in `src/input.js` so game code stays input-agnostic. Pointer lock does not exist on touch; never rely on it.
- **Detection**: decide touch UI with `matchMedia('(pointer: coarse)')` / `navigator.maxTouchPoints`, not the user agent. Show touch controls only on coarse pointers; a device can have both.
- **Layout/UI**: HUD and menus use relative units (`%`, `vw/vh`, `dvh`, `clamp()`) and flexbox/grid, no fixed pixel layouts. Tap targets >= 44px. Respect notches with `env(safe-area-inset-*)` (viewport already has `viewport-fit=cover`). Text readable at 360px width. No hover-only interactions. Add `touch-action: none` on the canvas and game controls so the browser does not scroll/zoom.
- **Resize/orientation**: anything sized to the screen (camera aspect, renderer, HUD) must react to `resize` (covers orientation changes). Use `visualViewport` where the on-screen keyboard or browser bars matter.
- **Performance**: mobile GPUs are weak. Respect the `graphics_quality` presets in `src/config.js` (cap DPR, shadow map size, draw distance); default to a lower preset on coarse-pointer devices. Avoid per-frame allocations; keep draw calls and texture sizes low.
- **Testing**: check every UI/input change at a phone viewport (e.g. 375x812 and landscape 812x375) with touch emulation, plus desktop, before calling it done.
